# 짝 단위 분할로 다시 만들기 사전등록

다시 돌리기 전에 썼다. 아래 "정한 것" 은 결과를 본 뒤 고치지 않는다. 틀린 곳을 찾으면 정정 줄로
남기고 규칙은 바꾸지 않는다.

## 왜 다시 만드는가

MSD Task04 의 볼륨 390개는 피험자 195명의 좌, 우 해마다. 지금 분할은 볼륨 하나를 단위로 무작위로 나눠, 같은 사람의 좌우가
홀드아웃과 개발셋, 또는 서로 다른 fold 로 갈릴 수 있다. 실제 규모를 쟀다.

- 짝 규칙: 번호 (31,32), (33,34) 처럼 홀수와 그다음 짝수가 한 사람이다(짝 키 `(번호 + 1) // 2`). 라벨 있는 260건으로
  이 규칙의 짝 90쌍과 무작위 짝 2,000번을 견줬다. 짝 사이 해마 부피 상관이 0.915 로 무작위(95% 범위 -0.21\~0.20)와
  확연히 다르고, 부피 비, 영상 크기, 밝기 분포, 밝기 배율도 무작위 2,000번 중 한 번도 이만큼 닮지 않았다. 한 칸 민 규칙
  (30,31)은 무작위와 비슷했다.
- 겹침 규모: 홀드아웃 52건 중 31건의 반대쪽 해마가 개발셋에 있다. 개발셋 5-fold 의 val 케이스는 fold 마다 41\~42건 중
  15\~23건(약 42%)의 반대쪽이 그 fold 의 train 에 있다.
- 진단: 홀드아웃에서 겹친 31건의 Dice 가 겹치지 않은 21건보다 0.0167 낮았다(짝 단위 부트스트랩 95% 구간
  [-0.0334, -0.0019]). 누수로 점수가 부푼 흔적은 없지만, 독립 단위가 16개뿐이라 영향이 없다고 말할 수는 없다.

그래서 분할을 짝 단위로 바꾸고, 분할에 기대는 결과를 전부 처음부터 다시 만든다.

## 정한 것

1. 짝과 단위
   - 짝 키는 `(번호 + 1) // 2` 다. 같은 키의 라벨 있는 볼륨이 둘이면 한 단위(짝), 하나면 그 볼륨이 한 단위다.
   - 라벨 있는 260건은 짝 90쌍(180건)과 혼자인 80건, 모두 170 단위가 된다.
2. 홀드아웃
   - 크기는 지금과 같은 52건(260 의 20%)으로 둔다. 시드는 `data.holdout_seed`(1234) 그대로다.
   - 단위 목록을 시드로 섞고 앞에서부터 더한다. 더하면 52건을 넘는 단위(51건일 때의 짝)는 건너뛰고 다음 단위로 간다.
     이렇게 정확히 52건을 채운다.
3. 개발셋 5-fold
   - 시드는 `data.fold_seed`(42) 그대로다. 개발셋의 단위 목록을 시드로 섞고, 차례로 볼륨이 가장 적은 fold 에 넣는다
     (같으면 번호가 작은 fold). 짝은 늘 한 fold 에 들어간다.
4. 결과를 모두 다시 만든다. 옛 분할의 결과는 어느 것도 새 결과와 섞지 않는다.
   - 절제실험: 기록된 설정 그대로 #1\~#3, #5\~#16, 시드 반복 #90\~#93, 모두 19회. #4 는 #1 과 설정이 같아 무효로 둔 회차라
     돌리지 않는다. 명령은 옛 기록 JSON 의 `config` 에서 만든다. 판정선 0.0039, 부모 대비 판정, 연속 미개선 3회 종료,
     추가 회차의 개선은 시드 반복으로 확인하는 규칙(`docs/prereg_ablation_extension.md`)을 그대로 쓴다. 새 결과에서
     종료 조건이 #16 까지 차지 않으면 그 규칙대로 회차를 더 돈다.
   - 쓰는 설정: 처음 회차(#13 까지) 최고값이 기준선보다 판정선 이상 높으면 그 설정, 아니면 기준선. 추가 회차는 시드
     반복까지 확인된 개선만 설정을 바꾼다. 지금 규칙과 같다. 결과가 #7 이 아닌 설정을 가리키면 그 설정으로 바꾼다.
   - 아키텍처 벤치마크: 쓰는 설정으로 SegResNet, SwinUNETR, UNet 을 5-fold 전부 400에폭. 선택은 지금처럼 CV Dice 최고값이다.
     이 CV 값은 체크포인트를 고른 val 에서 잰 값이라 모델마다 선택 이득이 다를 수 있다는 것을 표 옆에 적는다.
   - 홀드아웃 평가: 선택한 아키텍처의 fold 체크포인트 다섯 개로 52건, 부피 앙상블과 fold 별 값.
   - 배포: 선택한 아키텍처의 fold0 가중치를 `outputs/best_model.pth` 로 복사하고, ONNX FP32, FP16 내보내기와 parity, 지연 측정을
     다시 한다.
   - 화질 저하 부가 분석: `docs/prereg_degradation.md` 의 명령을 순서대로 모두 다시 돌린다(격자 조정은 원안과 넓힌 격자 둘 다,
     바이어스 비, 복원 U-Net 세 시드, 미세조정 다섯 fold, 평가). 판정 규칙은 그 문서 그대로다.
   - 일치도 재계산, 그림, 리포트도 새 결과로 다시 만든다.
5. 결론이 바뀌면
   - 아키텍처 선택, 쓰는 설정, 부가 분석 판정 가운데 무엇이 바뀌어도 새 결과를 최종으로 쓴다. 옛 분할로 돌아가지 않는다.
   - README 결과 절에는 새 결과만 적는다. 옛 결과와의 차이는 트러블슈팅 한 항목("분할을 짝 단위로 바꾸니 무엇이 얼마나
     움직였나")에 표로 적는다.
   - "홀드아웃이 CV 보다 높아 과적합 징후가 없다" 는 문장은 쓰지 않는다. 두 값을 나란히 적기만 한다. 체크포인트 선택 편향과
     분할 방식 차이가 섞여 원인을 가를 수 없기 때문이다.
6. 옛 결과의 보관
   - 다시 돌리기 전에 서버의 옛 산출물(절제 기록과 실행 폴더, 벤치마크, 부가 분석, 배포 모델, ONNX, 지연 측정, 리포트, 그림,
     `splits.json`)을 서버 보관 폴더로 옮긴다. 비교 표는 여기서 만든다. 지우는 것은 끝난 뒤 따로 정한다.
   - 이어받기 캐시는 `datamodule.py` 해시가 키에 들어 있어 분할 코드를 바꾸면 옛 fold 를 이어받지 않는다. 그래도 옛 실행
     폴더를 옮겨 두어 섞일 여지를 없앤다.
7. 검증
   - 테스트로 고정한다: 홀드아웃과 개발셋 사이에 갈린 짝이 없다, fold 사이에 갈린 짝이 없다, 홀드아웃은 52건, fold 크기 차이는
     2건 이하, 같은 시드면 같은 분할, `splits.json` 이 코드와 같다.
   - GPU 는 대기열로 한 번에 하나씩 쓴다.

## 결과를 보기 전에 더한 것 (학습 시작 전)

새 분할을 만들고(홀드아웃 52건, fold 42, 42, 41, 42, 41건, 분할 테스트 통과) 학습을 돌리기 전에 두 가지를 더한다.

1. 새 홀드아웃에는 같은 사람의 좌우가 함께 든 짝이 16쌍(32건) 있다. 개발셋과는 갈리지 않았지만 홀드아웃 안의 케이스끼리는
   독립이 아니다.
   - 화질 저하 부가 분석의 부트스트랩을 케이스 단위에서 피험자 단위로 바꾼다(`scripts/run_degradation.py` evaluate).
     `docs/prereg_degradation.md` 1번의 "케이스 부트스트랩"을 결과 보기 전에 바꾸는 것이고, 반복 수(1,000)와 시드(42),
     판정 규칙은 그대로다.
   - Bland-Altman 한계의 신뢰구간과 ICC 는 케이스를 독립으로 보는 식이다. 값은 그대로 내되, README 에 홀드아웃이
     피험자 36명의 52건이라는 것을 함께 적는다.
2. 부가 분석이 기준 모델 경로에 `segresnet` 을 네 곳 박아 두고 있었다. 벤치마크가 고른 구조(`selected_arch`)를 읽게 고쳤다.
   선택이 바뀌어도 부가 분석이 배포와 같은 모델을 쓴다.

## 결과를 보기 전에 더한 것, 두 번째 (절제 #1 의 첫 fold 가 끝나기 전)

절제 #1 이 시작했고 끝난 fold 는 아직 없다. 두 번째 검토 의견을 받아 아래를 더한다. 앞선 판의 sha256 은
첫 판 0eb1cb71585ee3b0..., 첫 추가 판 fa30df544e034764... 이다.

1. 쓰는 설정 고르기(4번의 둘째 줄을 정확히 한다)
   - 후보는 처음 회차(#13 까지) 가운데 기준선과 구조가 같은 회차다. 구조를 바꾼 #6 은 빼고, 구조는 아키텍처 벤치마크가 정한다.
   - 후보 최고값이 기준선보다 판정선 이상 높고, 그 설정과 기준선의 세 시드 평균끼리도 판정선 이상 차이가 나야 채택한다.
     시드 반복이 모자라면 기준선을 쓴다. 일지 생성기의 `adopted_setting()` 과 서버의 승자 반영 스크립트가 이 함수 하나를 쓴다.
     예전 함수는 판정선과 시드 확인 없이 최고값을 골랐다.
2. 처음 회차 최고가 #7 이 아닐 때
   - 새 최고 회차를 시드 43, 44 로 두 번 더 돌린다(#94, #95). 위 1번의 확인은 그 결과로 한다.
   - #92, #93(#7 의 시드 반복)과 #14\~#16(부모 #7)은 대기열대로 돌리고 기록에 남기되, 쓰는 설정이 #7 이 아니면 설정을
     바꾸는 데 쓰지 않는다.
   - 쓰는 설정이 #7 이 아니면 추가 회차를 그 설정 위에서 다시 센다. #14\~#16 과 같은 세 가지 변경(회전, 스케일 범위 절반,
     적용 확률 1.0, 강도 증강 뺌)을 적용할 수 있으면 #17\~#19 로 돌리고, 적용할 수 없는 변경은 절제 규칙대로 앞 회차 결과를
     보고 한 축씩 정한다(그때 가설을 이 문서에 먼저 적는다). 연속 미개선은 #17 부터 센다.
3. 대기열에 한꺼번에 넣은 19회
   - 처음 회차의 종료 판단은 예전처럼 부모 대비로 센 값을 보여 주기만 한다. 종료 조건이 #16 보다 먼저 차도 뒤 회차를 버리지
     않고 모두 기록에 싣는다. 쓰는 설정은 위 1, 2번 규칙으로만 정한다.
   - 쓰는 설정이 #7 이고 #14\~#16 에서 연속 미개선 3회가 차지 않으면 `docs/prereg_ablation_extension.md` 규칙대로 한 회씩 더 돈다.
4. 진단 문장 정정
   - 첫 절의 "누수로 점수가 부푼 흔적은 없다" 는 Dice 만 본 것이다. 같은 진단에서 주 지표인 ICC 는 겹친 쪽이 +0.056
     [-0.033, +0.268] 이었고, 한 칸 민 가짜 규칙에서도 ICC 차이가 -0.106 [-0.200, -0.047] 로 0 을 벗어났다. 부분집합 차이는
     어느 케이스가 들어갔는지에 좌우되므로 어느 방향으로도 진단으로 읽지 않는다.
5. 본 결과의 불확실성
   - 홀드아웃은 피험자 36명의 52건이다. ICC, Bland-Altman 편향과 한계, 비례편향 기울기에 피험자 단위 부트스트랩 구간
     (1,000회, 시드 42)을 함께 낸다. README 의 판단 문장(종단 추적, 비례편향 유무 등)은 케이스 독립 식과 피험자 부트스트랩이
     다르면 넓은 쪽을 따른다.
6. 화질 저하 부가 분석의 복원 U-Net 학습, 검증 나눔(개발셋 188 대 20)도 피험자 단위로 바꾼다. 검증은 학습률 조정과 조기종료에만
   쓰이지만 "짝을 가르지 않는다" 원칙의 예외를 두지 않는다. `docs/prereg_degradation.md` 수정 이력에 이 변경과 부트스트랩 변경을 적는다.
7. 다시 만든 뒤 고칠 문서와 파일(4번의 범위에 더한다)
   - README, `docs/EXPERIMENT_LOG.md`, `docs/MODEL_CARD.md`(개체 단위 분할 불가 한계 포함), `docs/CLAIM.md` 19번(분할 방법),
     `configs/default.yaml` 과 `src/hippo/config.py` 의 CV 수치 주석, `cli.py`, `run_ablation.py` 설명의 옛 수치와 옛 분할 서술.
   - `.gitignore` 가 절제 기록 JSON(`outputs/ablation/*.json`)을 저장소에 넣게 고친다.
   - README 에 "TensorRT FP16 엔진의 분할 정확도는 홀드아웃에서 재지 않았다(ONNX FP32 parity 만 확인)" 를 적는다.
   - 짝 가정 검증을 저장소 안으로 옮긴다(`scripts/check_subject_pairs.py`, 결과 `outputs/subject_pairs.json`). 390개 전체가 결번
     31, 32, 85, 86 을 빼고 짝 키 195개로 정확히 두 개씩 묶인다는 구조 근거와, 닮음이 가장 낮은 짝 몇 개를 함께 싣는다.
   - 노트북 최종본의 `outputs/splits.json` 을 새 분할로 맞춘다. `scripts/export_splits.py` 는 `cfg.data.fold_seed` 를 넘기게 고친다
     (지금은 기본값 42 가 우연히 같다).
   - 부가 분석 부트스트랩이 피험자를 한 단위로 뽑는지를 소스 문자열이 아니라 작은 가짜 데이터로 확인하는 테스트로 바꾼다.
