# Model Card: 해마 3D 분할과 부피 정량화

## 개요
- 과제: 뇌 MRI에서 해마(anterior/posterior) 3D 분할 -> 부피 정량화
- 데이터: Medical Segmentation Decathlon Task04 Hippocampus (CC-BY-SA 4.0)
- 대상: Vanderbilt University Medical Center 한 기관, 성인 195명(건강인 90명, 비정동성 정신병 105명),
  3D T1 강조 MPRAGE, Philips Achieva. 공개 볼륨은 좌우 해마 crop 임(README 데이터 출처)
- 클래스: 0=배경, 1=anterior, 2=posterior (out_channels=3)
- 백본: MONAI 3D `SegResNet`(기본) / `UNet` / `SwinUNETR` 선택 가능

## 입력/전처리
- NIfTI(.nii/.nii.gz), 단일 채널
- RAS 방향통일 -> 1mm isotropic resampling -> z-score(nonzero) 정규화
- 학습: ROI 64³ 패딩 + 증강 `spatial-wide`(좌우 flip, RandAffine 회전 +/- 30도, 스케일 +/- 20%, 강도 증강).
  절제실험이 고른 설정(#11, 세 시드 평균으로 확인)이고 배포 가중치를 만든 벤치마크도 이 설정으로 학습함

> ROI 를 64³ 로 정한 근거 (실측)
> 1. Task04 학습 볼륨 260개의 최대 단일 축이 59 -> 64³ 는 전 볼륨을 잘림 없이 담음.
> 2. SwinUNETR 는 patch_size 2 x 4단계 다운샘플링(32배 축소) 구조라 32³ 입력이
>    1x1x1 로 붕괴해 InstanceNorm 이 실패함. 실행 가능한 최소 크기가 64³ 임.
>
> 64³ 는 세 아키텍처를 같은 입력으로 공정 비교할 수 있는 최소 크기임.
> ROI 가 볼륨 전체를 덮으므로 랜덤 크롭은 no-op 이 되어 전체 볼륨 학습으로 전환됨
> (`crop_samples=1`, 동일 샘플 4중복 생성 방지).

## 학습 설정
- Loss: DiceCE (softmax, to_onehot_y)
- Optimizer: Adam, ReduceLROnPlateau(mode=max on Dice)
- AMP, Gradient Accumulation, EarlyStopping(patience=20)
- seed 고정(determinism), best = val Dice 기준 체크포인트

## 평가
- 분할: Dice, HD95, ASD (background 제외), 5-fold CV mean +/- std. 표면 거리는 1mm 공간의 mm 단위임.
  예측이나 정답 한쪽이 비면 MONAI 가 거리를 inf 로 돌려주고 평균도 inf 가 됨. 보고한 평균이 모두
  유한하므로 이번 평가에는 빈 예측이 없었음.
- LoA 신뢰구간: Bland & Altman(1986)대로 SE = sqrt(3 s²/n) 에 자유도 n-1 의 t 값(n=52 에서 2.008)을 곱함.
- 부피 신뢰도(핵심): 예측부피 vs 정답부피 ICC(2,1) + Bland-Altman(bias, 95% LoA)
  - 근거: 높은 Dice가 정확한 부피를 보장하지 않음 -> 측정 신뢰도를 별도 검증
- 공간 주의: 부피는 1mm resampling 공간에서 측정(voxel=1mm³). 임상 정확도를 위해선
  native space 역변환 또는 resampling 보정 권장(코드에 `space` 필드로 명시).

## 성능 (개발셋 5-fold CV n=208 + 홀드아웃 n=52)

### 실험 설계

```
260개  ->  개발셋 208 (5-fold CV, 모델 선택)  +  홀드아웃 52 (최종 1회 평가)
```

홀드아웃은 체크포인트 선택, 아키텍처 선택에 일절 사용하지 않음.
홀드아웃 시드는 학습 시드와 분리해 고정함.

분할 단위는 피험자임. 같은 사람의 좌, 우 해마(파일 번호 (31,32), (33,34) 같은 짝)는 홀드아웃과 개발셋, fold 사이에
갈리지 않음(한계 3, `docs/prereg_pair_split.md`). 홀드아웃 52건은 피험자 36명이고 16쌍이 좌우를 함께 담음.

### 아키텍처 비교 (개발셋 5-fold CV, n=208)

| 모델 | Dice | HD95 | ASD |
|---|---|---|---|
| UNet | 0.8789 +/- 0.0016 | 1.48 | 0.471 |
| **SegResNet** (선택) | **0.8878 +/- 0.0025** | 1.41 | 0.436 |
| SwinUNETR | 0.8865 +/- 0.0034 | 1.48 | 0.440 |

> SegResNet 와 SwinUNETR 의 차이는 0.0013 으로 fold 간 표준편차(0.0016\~0.0034)보다 작음.
> "SegResNet 가 더 낫다"고 주장할 근거는 없음. CV 최고값으로 하나를 골라야 해서 골랐을 뿐이고, 같은 값이면 가벼운 쪽이라는 실용적 근거가 겹침.
> 의미 있는 것은 UNet 대비 우위(+0.0089) 뿐임. 이 CV 값은 체크포인트를 고른 val 에서 잰 값이라 모델마다 선택 이득이 다를 수 있음.

### 홀드아웃 최종 평가 (n=52, 모델 선택에 미사용)

| 지표 | 값 |
|---|---|
| Dice | 0.8884 +/- 0.0017 |
| HD95 | 1.40 |
| ASD | 0.433 |

문헌의 nnU-Net 계열 보고치(Dice 약 0.89\~0.90)에 근접함.
홀드아웃 Dice(0.8884)와 CV Dice(0.8878)는 나란히 적기만 함. CV 값에는 체크포인트 선택 편향이 들어 있고 두 값은 다른
케이스 묶음에서 잰 것이라, 차이를 과적합 유무로 읽지 않음.

### 부피 일치도

5개 fold 체크포인트가 낸 부피를 케이스별로 평균한 단일 예측 기준 (n=52). 마스크를 합친 앙상블이 아니라 부피의 평균임.
배포되는 `best_model.pth` 는 fold0 한 장이고 그 가중치의 값은 ICC 0.9006,
bias +124.9mm³, LoA 반폭 9.5% 임(ICC, bias 모두 다섯 중 둘째). 경위와 바꾸지 않은 이유는
`docs/report.md` 의 "배포하는 것과 보고하는 것" 에 적었음.

| 지표 | 값 |
|---|---|
| ICC(2,1) | 0.8972 |
| Pearson r | 0.9405 |
| bias (예측−정답) | +133.4 mm³ (+4.23%) |
| 95% LoA | [−157.7, +424.5] mm³ (폭 582.2) |
| LoA 상한 95% CI | [352.9, 496.1] |
| LoA 하한 95% CI | [−229.3, −86.1] |
| 평균 절대 백분율 오차 | 5.00% |
| LoA 반폭 | 참조 평균(3,152mm³)의 9.2% |
| 체크포인트별 ICC | 0.8940 +/- 0.0100 |
| 정답 부피 | 평균 3,152 mm³ (범위 2,397\~4,383) |

> ICC 는 체크포인트별로 n=52 씩 따로 계산함. 5개 예측을 한 배열에 합치면
> 같은 개체가 5번 들어가 독립성 가정이 깨지고 n 이 5배로 부풀려짐.
> ICC(2,1) 은 독립 개체를 전제하는 지표임.
>
> ICC 구현은 Shrout-Fleiss ICC(2,1)(two-way random, single measure, absolute agreement)
> 공식을 따르며, 독립 구현과 소수점 6자리까지 일치함을 확인함.

홀드아웃에 같은 사람의 좌우가 함께 들어 있어 피험자 단위 부트스트랩 구간(36명, 1,000회, 시드 42)도 냄.
ICC [0.809, 0.943], bias [92.9, 176.8] mm³, LoA 하한 [−225.4, −92.1], 상한 [330.6, 518.8], 비례편향 기울기
[−0.148, 0.077]. LoA 상한은 케이스 독립 식의 구간보다 약 31% 넓음(폭 188.2 대 143.2).

## 안전/QC
- 입력검증: 3D 여부, NaN/Inf, spacing, 방향, 강도 sanity (하드 실패/소프트 경고).
  보고하는 `dtype` 은 파일에 저장된 자료형임: 내부에서 float32 로 변환한
  뒤의 값을 보고하면 무엇을 넣든 항상 `float32` 가 되어 검증기가 정작 확인해야 할
  것을 감춤(수정 완료).
- 출력 QC: 최대 연결성분 유지(노이즈 섬 제거), 부피 타당범위 플래그.
  QC 판정은 정제 전 마스크로 함: `keep_largest_component()` 를 먼저
  적용하면 라벨당 연결성분이 하나뿐이라 파편화 검사가 절대 발동하지 않아, 원본이
  아무리 노이즈투성이여도 리포트가 "파편화 없음"이라고 말함(수정 완료).
  정제로 제거된 복셀 수는 `cleanup_removed_voxels` 로 함께 남김.
- 불확실도 추정(MC dropout)과 TTA 는 구현하지 않음(향후 과제)

## 배포
- PyTorch -> ONNX(opset18, dynamic batch) -> TensorRT FP16(엔진 빌드 코드 포함)
- parity: logits 최대오차 + argmax 라벨 일치율 두 축
- TensorRT 런타임으로 패치 추론(FP16), MONAI sliding window와 결합
- 벤치마크: PyTorch FP32 / ONNXRuntime / TensorRT FP16 (latency, throughput, VRAM)

## 한계

자체 감사로 찾아낸 것들임.

### 1. 측정 정밀도가 종단 추적에는 부족함

ICC 0.8972는 교과서 기준 "좋은 일치도"(0.75\~0.9)의 윗부분임. 그러나 95% LoA 폭이 582.2mm³,
평균 부피(3,152mm³)의 +/- 9.2% 임. 개별 케이스 예측이 그만큼 흔들릴 수 있음.

해마 위축은 건강한 노화에서 연 1.41%, 알츠하이머에서 연 4.66% 진행함(메타분석 문헌값).
측정 오차가 연간 변화의 약 2\~6.5배임. 한 사람의 연간 변화를 추적할 수 없음.

| 용도 | 가능 여부 |
|---|---|
| 단면 비교 (정상군 대비 위축 여부 선별) | 조건부 가능. 정상군 기준값도 같은 도구로 잰 값이어야 함(한계 2) |
| 종단 추적 (같은 사람의 연간 변화 측정) | 불가 |

높은 Dice 가 정확한 부피를 보장하지 않듯, 높은 ICC 도 임상적으로 쓸 만한 정밀도를 보장하지 않음.

### 2. 부피를 전 구간에서 고르게 크게 측정함(평균 +4.2%)

예측 부피가 정답보다 평균 +133.4mm³(+4.23%) 큼. 52건 중 40건이 과대추정이고, 다섯 fold 체크포인트가 모두
+106.2\~+159.9mm³ 로 같은 방향임. Pearson r 은 0.9405 로 높아 크고 작은 순서는 잘 맞히지만, ICC(2,1)은 절대 일치를
보므로 이 편향만큼 낮음(0.8972). 편향을 빼고 보는 일관성 ICC(3,1)은 0.9398 임(`ensemble_agreement.icc_3_1_consistency`).

비례편향은 유의하지 않음. 차이(diff)를 평균(mean)에 회귀시킨 결과:

```
기울기 −0.039,  r = −0.112,  p = 0.431
```

피험자 부트스트랩 구간 [−0.148, 0.077] 도 0 을 포함함. 편향은 크기에 따라 달라지기보다 전 구간에 고르게 있어, 단일
LoA 로 요약하는 데 걸림이 없음. 52건에서는 이 크기의 기울기가 유의성 경계를 쉽게 오감(옛 분할의 경위는 트러블슈팅 3,
10, 12).

편향을 홀드아웃에서 재서 빼는 보정은 하지 않음. 홀드아웃으로 보정값을 정하면 그 뒤의 값은 미리 보지 않은 성능이
아니게 됨. 임상 적용 시에는 정상군 기준값도 같은 도구로 잰 값이어야 함.

### 3. 피험자 단위 분할은 추정한 짝 규칙에 기댐

MSD Task04의 각 볼륨은 해마 하나 주변 crop임(실측 약 35x51x35 @ 1mm).
출처는 건강인 90명 + 비정동성 정신증 환자 105명 = 195명이고 공개 볼륨은 390개
(train 260 + test 130) -> 피험자당 2개(좌, 우). 좌우 해마는 같은 뇌, 같은 스캐너, 같은 세션, 같은 위축 상태를
공유하므로 독립이 아님.

MSD는 피험자와 파일의 대응을 공개하지 않음. 파일명은 `hippocampus_001` 같은 일련번호뿐임. 그래서 짝을 자료로
추정함(`scripts/check_subject_pairs.py`, `outputs/subject_pairs.json`).

- 홀수와 그다음 짝수를 한 사람으로 보면 390개가 결번 31, 32, 85, 86 을 빼고 짝 키 195개에 정확히 두 개씩 묶임.
- 라벨 있는 짝 90쌍의 부피 상관은 0.915 로 무작위 짝 2,000번(95% 범위 -0.21\~0.20)과 확연히 다르고, 영상 크기와
  밝기 분포도 무작위 2,000번 중 한 번도 이만큼 닮지 않음. 한 칸 민 규칙은 무작위와 비슷함.

이 규칙으로 홀드아웃과 개발셋 5-fold 를 피험자 단위로 나눔. 남는 한계는 두 가지임.

- 짝은 확인이 아니라 추정임. 규칙에 맞지 않는 짝이 있으면 그만큼 누수가 남음.
- 홀드아웃 52건 안에는 같은 사람의 좌우 16쌍이 함께 있음. 케이스를 독립으로 보는 ICC 와 LoA 신뢰구간은 실제보다 좁을
  수 있어 피험자 단위 부트스트랩 구간을 함께 냄.

MSD 공식 train/test 분할도 이 규칙으로 보면 195쌍 중 80쌍을 가름. 이 데이터셋을 볼륨 단위로 나누는 연구는 같은
구조를 공유함.

### 4. 아키텍처 선택의 근거가 약함

SegResNet(0.8878)과 SwinUNETR(0.8865)의 CV Dice 차이는 0.0013 으로
fold 간 표준편차(0.0016\~0.0034)보다 작음. 두 모델은 실질적으로 구분되지
않음. 볼륨 단위 분할에서 100에폭 한도로 돌던 첫 벤치마크는 순위가
반대였고(SwinUNETR 0.8793 > SegResNet 0.8783), 에폭 한도와 증강을 바꾸자 1위가
바뀌었다는 사실 자체가 이 차이를 믿을 수 없다는 증거임(트러블슈팅 7, 10번).

CV 최고값으로 하나를 골라야 해서 SegResNet 를 골랐을 뿐이며,
"SegResNet 가 더 낫다"는 주장은 이 데이터로 뒷받침되지 않음.
의미 있는 것은 UNet 대비 우위(+0.0089) 뿐임.

> 계산 비용도 SwinUNETR 가 훨씬 큼(초기 측정 1 epoch 45.6s vs SegResNet 16.9s).
> 성능이 구분되지 않으므로 가벼운 쪽을 씀.

## 해결된 한계 (기록)

### 보고된 성능의 낙관 편향: 홀드아웃 분리로 제거함

초기 감사에서 발견: 체크포인트를 val Dice 최대 에폭에 저장하고
그 체크포인트를 같은 val fold 에서 다시 평가해 보고하고 있었음.
발견 근거: 당시 결과 파일에서 `best_dice` 와 `dice` 가 소수점 16자리까지 동일함.
같은 값을 두 번 적은 것이며, val 최고점을 그대로 성능으로 보고했다는 뜻임.
(해당 파일은 잘못된 값이므로 폐기했고, 현재 저장소에는 재설계 이후 결과만 있음.)
전형적인 winner's curse 였음.

조치: 260개 중 52개를 홀드아웃으로 분리해 체크포인트 선택, 아키텍처 선택에
일절 사용하지 않고, 최종 1회만 평가하도록 실험을 재설계함.

결과: 홀드아웃은 모델 선택에 쓰이지 않은 값이 됨. 홀드아웃과 CV 의 차이는 과적합 유무로 읽지 않음
(위 홀드아웃 최종 평가).

### 홀드아웃 ICC 의 독립성 위반: 계산 방식을 고침

fold 체크포인트 5개를 같은 홀드아웃 52건에 적용한 뒤 예측을 한 배열에 누적해
ICC 를 계산하고 있었음. 같은 개체가 5번 들어가 n 이 5배로 부풀려지고
개체 간 분산이 왜곡됨. ICC(2,1) 은 독립 개체를 전제하는 지표임.

조치: 체크포인트별 n=52 계산(mean +/- std)과 앙상블 단일 예측 n=52 계산으로 분리.

### 비례편향, LoA 신뢰구간 미산출: 구현함

구현했을 때는 비례편향이 유의했지만(p = 0.024, 볼륨 단위 분할), 재학습과 재계산 때마다 p 가 움직였고 지금은 유의하지 않음(한계 2).

### 같은 사람의 좌우가 홀드아웃과 개발셋에 갈리던 분할: 피험자 단위로 나눔

볼륨 하나를 단위로 나눠, 옛 홀드아웃 52건 중 31건의 반대쪽 해마가 개발셋에 있었음. 짝 규칙을 자료로 확인한 뒤
결과를 보기 전에 사전등록(`docs/prereg_pair_split.md`)을 쓰고, 분할을 피험자 단위로 바꿔 절제, 벤치마크, 홀드아웃,
배포, 화질 저하 분석을 전부 다시 만듦. 무엇이 얼마나 움직였는지는 트러블슈팅 16(`docs/TROUBLESHOOTING.md`).
